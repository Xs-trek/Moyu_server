# Moyu v0.0.4 release audit

Audit date: 2026-08-24 (Asia/Singapore)

## Boundary confirmed

- Claude Code and Codex remain native CLI adapters.
- OpenCode uses only the official loopback OpenCode Server REST/SSE API.
- Attach mode neither requires nor stops an OpenCode executable/process.
- Managed mode uses a local OpenCode executable only to start one owned
  `opencode serve`; all Session/Message/Event/Permission/History/Abort interaction still uses the
  Server API.
- Provider credentials, OpenCode Server credentials and PC-local Server configuration are not
  projected to Android or accepted from its configuration patch API.
- No adapter sends frontend/device/network/product metadata in model input.

## Verification completed

- Backend `npm run typecheck`: passed.
- Backend complete `npm test`: passed, including provider-surface 18/18, egress 790/790,
  OpenCode Server 34/34 and gateway integration 99/99.
- Isolated real-runtime OpenCode smokes passed against both 1.17.9 and 1.18.19: health,
  authenticated global SSE, Session creation, Message listing, Abort and clean managed shutdown.
- Windows x64 single-binary build: passed all pre-build outbound/provider/hook surface gates and
  the stripped-PATH embedded EasyTier/local approval self-check.
- Web UI production build: passed.
- Web UI static/contract matrix: 90/90 passed, including 35 fixtures in light/dark data states.
- Android: 61 Gradle tasks passed, including unit tests, debug lint (no issues), R8 release build,
  native-library hashes, APK content/identity inspection and signature verification.
- No project-specific Vite, Gradle, Moyu or EasyTier process remained after the gates.

## Explicit remaining acceptance boundary

This host has OpenCode Desktop 1.17.9. Its internal sidecar generates an application-private random
password per launch, so it is intentionally not an attach target and was not scraped. Instead, the
release gate used isolated official `opencode serve` runtimes at both ends of the supported range:
1.17.9 and 1.18.19. Both authenticated REST/SSE smokes passed without selecting a provider/model or
making a provider request.

OpenCode Desktop sharing therefore uses the documented one-time setup: Desktop is pointed at the
stable Moyu-managed loopback Server printed by `moyu -init`. Dynamic interaction and visual
acceptance on a physical Android device remain the user's acceptance step; repository-side static,
contract, real-runtime, JVM and build gates are closed.
